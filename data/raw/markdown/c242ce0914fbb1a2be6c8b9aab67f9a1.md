#   ⟨60⟩ ubs_ai — синтетический tool-use CoT датасет для утилиты ubs (BPMSoft) 
Обучающие примеры корректного вызова инструментов CLI/MCP-утилиты **ubs** (администрирование и разработка конфигурации BPMSoft — форк Creatio). Каждый пример: запрос пользователя на русском → рассуждение `<think>…</think>` → вызов правильного инструмента строго по схеме.
Формат хранения — **Parquet** (zstd). Сплиты: `train` / `validation`.
##   ⟨56⟩ Состав 
  * **Всего:** 2700 записей (2430 train / 270 validation)
  * **Команд покрыто:** 332 / 332 (каждая 4–9 примеров)
  * **Surface:** MCP-тулы + CLI-вербы
  * **Kind:** positive (вызов), negative (нет обязательных данных → переспрос без вызова), irreversible (необратимая операция: план → подтверждение человека → дословный повтор вызова), recovery (инструмент вернул isError → вызов исправлен по тексту ошибки)
  * **Язык:** запрос и названия объектов — русский; verb/флаги/code/env — английский
  * Детерминированный gate: 100% строк проходят валидацию по эталонной схеме (arguments⊆properties, все required, enum, CLI-флаги, GUID-provenance: неугадываемые значения обязаны присутствовать в тексте запроса и дословно копироваться в аргументы).

###   ⟨58⟩ Быстрый старт в Unsloth / Fine-tuning Studio 
Конфиг по умолчанию **chat** — 3 плоские текстовые колонки `system` / `user` / `assistant` (single-turn). Имена колонок совпадают с ролями → **role-mapper Fine-tuning Studio авто-мапит их без ручной разметки** (`user`→user, `assistant`→assistant, `system`→system). Вызов инструмента — внутри колонки `assistant` тегом `<tool_call>…</tool_call>` (после `<think>…</think>`).
Для кода Unsloth/TRL любой из форматов:

```
from datasets import load_dataset
from unsloth.chat_templates import standardize_sharegpt
ds = load_dataset("Catter58/ubs_ai", "sharegpt")   # conversations[] from/value
ds = standardize_sharegpt(ds)                       # from/value → role/content
trainer = SFTTrainer(train_dataset=ds["train"], eval_dataset=ds["validation"], ...)

```

Либо конфиг **text** (готовая ChatML-строка), обучать напрямую БЕЗ chat-template (`dataset_text_field="text"`). Не применяйте `apply_chat_template` к конфигу **text** — строка уже собрана (пустой `text` после повторного шаблонирования = `IndexError: string index out of range`).
Схемы Parquet:
  * **chat** (default) — колонки `system`, `user`, `assistant` (str, single-turn). Имена = роли → авто-детект role-mapper'а. Вызов инструмента в `assistant` тегом `<tool_call>…</tool_call>`. Конфиг **chat** содержит только однотёрновые записи (positive/negative); мультитёрн (irreversible/recovery) доступен в конфигах `sharegpt`, `text`, `messages`.
  * **sharegpt** — ЕДИНСТВЕННАЯ колонка `conversations` (list<struct<`from`, `value`>>; `from`∈ system/human/gpt — **только эти три**). Без meta-колонок. Вызов инструмента внутри `value` тегом `<tool_call>{"name":…,"arguments":…}</tool_call>`. В мультитёрновых записях (`kind`=irreversible/recovery) роль `tool` (ответ инструмента, например `isError`/подтверждение) **переписана в`from:"human"`** , содержимое обёрнуто тегом `<tool_response>…</tool_response>` — как в glaive-style function-calling датасетах. Причина: у Unsloth `standardize_data_formats`/`standardize_sharegpt` нет алиас-бакета `tool` (только system/human/gpt) и он падает `TypeError: Unsloth: ['tool'] are not in aliases.` на сырой роли; ремаппинг сохраняет чередование human/gpt, которого требует `standardize_sharegpt`. **`messages`и`text` ниже роль `tool` НЕ трогают** — там она сырая.
  * **text** — колонки: `text` (str, ChatML: `<|im_start|>role\n…<|im_end|>`, вызов инструмента внутри ассистента тегом `<tool_call>…</tool_call>`), `command`, `surface`, `kind`, `behavior`. Роль `tool` (мультитёрн) хранится как есть — `<|im_start|>tool\n…<|im_end|>`, без ремаппинга.
  * **messages** — колонки: `messages` (list<struct<`role`, `content`, `tool_calls`>>), `command`, `surface`, `kind`, `behavior`. `tool_calls` — **JSON-строка** `[{"name":…,"arguments":…}]` (аргументы вариативны по команде, поэтому сериализованы; `null` у system/user). Роль `tool` (мультитёрн) хранится как есть — БЕЗ ремаппинга (в отличие от sharegpt выше).


`behavior`: RO=read-only, D=destructive, I=idempotent.
##   ⟨59⟩ Генерализация 
`environment` и неугадываемые идентификаторы (GUID/Id/uid) **берутся из запроса и дословно копируются** в аргументы — модель учится ИЗВЛЕКАТЬ значения, а не заучивать конкретный стенд.
