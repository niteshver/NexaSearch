#   ⟨54⟩ Code Review Findings Samples 
Curated **synthetic examples** for evaluating automated code review pipelines — especially the AI Code Reviewer MCP⟨55⟩ stack built with Qwen3.6-27B⟨56⟩.
Each row contains a short code snippet, the analysis type, and a structured JSON output that matches the review contract used by ImTamsi/qwen3.6-27b-code-reviewer⟨57⟩.
##   ⟨49⟩ Dataset structure   
| Column  | Description  |  
| --- | --- |  
| `id`  | Stable sample identifier  |  
| `analysis_type`  |  `review`, `bugs`, `security`, `performance`, `tech_debt`, or `tests`  |  
| `language`  | Source language (`python`, `typescript`, `javascript`, `go`, …)  |  
| `file_path`  | Virtual path inside a repository  |  
| `repo_context`  | One-line description of the fictional codebase  |  
| `code_snippet`  | Code under review  |  
| `findings`  | Structured object (`summary` + `findings[]`)  |  
| `findings_json`  | Same object serialized as JSON string for easy prompting  |  
##   ⟨50⟩ Intended use 
  * Prompt regression tests for LLM code reviewers
  * Few-shot examples in Gradio / MCP demos
  * Schema validation fixtures for JSON output parsers


##   ⟨51⟩ Limitations 
  * Samples are **hand-authored** , not mined from production codebases
  * Findings illustrate expected shape and severity — not ground-truth audits
  * Always have a human validate security-critical results
