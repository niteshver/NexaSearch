#   ⟨59⟩ OpenResearcher → Qwen3.5 SFT 
6003 deep-research agent trajectories for supervised fine-tuning of `Qwen/Qwen3.5-9B`, converted from OpenResearcher/OpenResearcher-Dataset⟨60⟩ (Harmony format) into OpenAI-style chat turns, stored as zstd-compressed Parquet.
Each row is one example:
  * `qid` — row id within its source seed split
  * `messages` — `system`, `user`, then alternating `assistant` / `tool` turns:
    * assistant reasoning is wrapped in `<think>...</think>` at the start of the turn
    * tool calls are an OpenAI-style `tool_calls` list (`browser.search`, `browser.open`, `browser.find`)
    * tool results are `role: "tool"` messages with a matching `tool_call_id`
    * the final assistant turn contains the answer
  * `tools` — the function-calling schema for the three browser tools, ready to pass to `tokenizer.apply_chat_template(messages, tools=...)`


Note: Arrow unifies the schema across rows, so optional fields (`tool_calls`, `tool_call_id`, `name`, and unused keys inside `tools[*].function.parameters.properties`) appear as `None` where absent — filter out `None` values before passing to a chat template if yours doesn't ignore them.
##   ⟨56⟩ Processing 
From the source dataset's `seed_*` splits: trajectories with corrupted Harmony artifacts (~14%) were dropped whole rather than repaired, trajectories over 131,072 Qwen3.5 tokens were dropped (not truncated, to avoid orphaning tool calls), and exact duplicate questions across seeds were removed (one trajectory per unique question). Mean length is ~47k tokens.
##   ⟨57⟩ Configs 
  * `default` — 5,939 trajectories up to 131,072 Qwen3.5 tokens
  * `64k` — the 5,359 of those trajectories that fit in 65,536 tokens, for training runs with a 64k sequence length (pre-filtered so no trajectory gets truncated mid-tool-call)
  * `32k` — the 2,535 of those trajectories that fit in 32,768 tokens, for training runs with a 32k sequence length (pre-filtered so no trajectory gets truncated mid-tool-call)


##   ⟨58⟩ Usage
