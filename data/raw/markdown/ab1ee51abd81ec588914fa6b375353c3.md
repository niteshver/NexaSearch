#   ⟨54⟩ Putusan structured-extraction dataset 
Built 2026-07-08T23:02:28+00:00 by `notebooks/build_dataset.py` (seed 3407).
Indonesian court-decision (putusan) extractive-structuring dataset over three corpora (Anak, Asusila, TPPO). Each row is one model extraction of one source document into 31 canonical sections of verbatim spans. Empty sections were completed from sibling model extractions of the same document where available (`cross_model_fill_json` records per-section donor provenance).
##   ⟨50⟩ Files 
`{sft,grpo,rag}/{train,val,test}.parquet` — purposes are document-disjoint (SFT 70% / GRPO 15% / RAG 15% of unique documents per corpus), then each purpose is split train 80% / val 10% / test 10%. All rows of a document (one per annotator model) share the same purpose+split, so there is zero document leakage across any pair of files.

##   ⟨53⟩ `sft_sections` config (per-section SFT) 
Derived from the `sft` config by `notebooks/build_sections_dataset.py` — same documents, same document-disjoint splits, zero leakage. Each parent document becomes SIX examples that keep the FULL reconstructed body as input but ask for only 1-2 sections (matching inference, where a user uploads a whole decision and asks for one or two sections). The 31-key `sft` config is unchanged.
Section sampling is deterministic and difficulty-weighted (measured on `sft/train.parquet`): `ahli` (67% empty) is asked for every document; `penangkapan`/`surat` (29%/16% empty) alternate; two of the five long-body sections (`pertimbangan_hukum`, `saksi`, `dakwaan`, `terdakwa`, `fakta_hukum`) rotate; one medium section (`tuntutan`, `penahanan`, `petunjuk_barang_bukti`, `amar_putusan`) rotates; and one PAIR of the 19 trivial identity/date sections rotates (this is the two-section example). ~16% of examples ask for a section that is empty in that document, so the model learns to answer with an empty list.
Extra/changed columns vs the parent schema: `parent_id` (the `sft` row id), `requested_sections` (list), `n_requested`, `n_empty_requested`; `target_json`/`answer` contain only `{"sections": {...}, "empty_sections": [...]}` for the requested keys; the system prompt names the requested sections. Columns about the full 31-section extraction (`sections_json`, `cross_model_fill_json`, etc.) are omitted. 7 exact-duplicate parent train rows (same sha under two filenames) are dropped.
