#   ⟨64⟩ StyleMix-Tulu 
**StyleMix-Tulu** is a style-augmented instruction-tuning dataset. Each source instruction from the Tulu v3 SFT mixture is rewritten into four additional stylistic variants while preserving its underlying intent, yielding paired data for studying how instruction _phrasing_ affects model behavior. It is intended for work on instruction-following robustness, style-invariance, and instruction fine-tuning where surface-form diversity matters.
##   ⟨55⟩ Motivation 
Instruction-tuned models are typically trained on instructions written in a single, clean register. Real users write casually, verbosely, with awkward constraints, or with adversarial framing. StyleMix-Tulu holds the _task_ fixed while systematically varying the _style_ of the instruction, so that models and training methods can be evaluated on whether they generalize across how a request is phrased rather than just what it asks.
##   ⟨56⟩ Dataset structure 
Every original instruction expands into up to five rows sharing the same task, distinguished by the `group_id` field:  
| `group_id`  | Instruction  | Response  |  
| --- | --- | --- |  
| `original`  | The unmodified Tulu instruction  | Original gold response  |  
| `casual`  | Informal rewrite: lowercase, slang, minor typos  | Original gold response  |  
| `verbose`  | Padded with hedging and filler context  | Original gold response  |  
| `adversarial`  | Deceptive / misdirecting framing (e.g. injection-style), intent preserved  | Original gold response  |  
| `constrained`  | Adds formatting constraints (length, format, etc.)  |  **Newly generated** response satisfying the constraints  |  
For `casual`, `verbose`, and `adversarial`, only the instruction changes; the original response remains valid and is reused. For `constrained`, the added constraints usually invalidate the original response, so a new response was generated to satisfy them.
###   ⟨57⟩ Fields 
  * `instruction` (string): the (possibly rewritten) instruction
  * `response` (string): the target response
  * `group_id` (string): one of `original`, `casual`, `verbose`, `adversarial`, `constrained`
  * `source_subset` (string): the originating Tulu v3 source (e.g. `ai2-adapt-dev/numinamath_tir_math_decontaminated`)
  * `source_bucket` (string): same as `source_subset` (retained for schema compatibility)

##   ⟨59⟩ How it was built 
  1. **Source & filtering.** Streamed the full `allenai/tulu-3-sft-mixture` (shuffled, seed 42). From each conversation, the first user turn was taken as the instruction and the following assistant turn as the response. Rows were kept only if the instruction was 10–4000 characters and the response ≤8000 characters. {FILTERED_COUNT} inputs survived filtering.
  2. **Augmentation.** Each surviving instruction/response pair was sent to **Qwen2.5-7B-Instruct** (bf16, served with vLLM) with a fixed prompt asking for the four style rewrites as a single JSON object. Sampling: temperature 0.7, top-p 0.9, max 1200 new tokens; one retry at temperature 0.2 on JSON parse failure.
  3. **Expansion.** Each parsed result was expanded into the five-row structure above and written to JSONL.


##   ⟨60⟩ Intended uses 
  * Training or fine-tuning instruction-following models with style diversity
  * Evaluating robustness / invariance to instruction phrasing
  * Studying distributionally-robust or style-controlled training objectives
  * Paired analysis: the shared task across `group_id`s enables controlled comparisons of model behavior under fixed intent, varied surface form


##   ⟨61⟩ Limitations & biases 
  * **Augmentation-model artifacts.** Rewrites and the regenerated `constrained` responses were produced by Qwen2.5-7B-Instruct and inherit its limitations and biases. The `constrained` responses in particular are model-generated, not human-verified.
  * **Adversarial group.** These instructions use injection-style or misdirecting framing for robustness research. They are intended as _training/evaluation signal_ , not as validated attacks, and should not be treated as a security benchmark.
  * **English-centric.** Filtering and rewriting were tuned for English; other languages present in Tulu may be underrepresented or lower quality.
  * **Parse-failure skew.** Inputs whose augmentation failed to parse appear only as `original` rows, very slightly biasing the augmented subsets toward easier-to-format instructions.
