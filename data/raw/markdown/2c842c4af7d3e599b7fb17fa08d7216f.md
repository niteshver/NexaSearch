#   ⟨36⟩ ONNX Resize Inference DoS ModelScan Bypass 
##   ⟨37⟩ Target 
ONNX model format.
##   ⟨38⟩ Summary 
`onnx_resize_inference_dos.onnx` is a 189-byte ONNX model that passes ONNX validation, passes ONNX shape inference, and loads successfully in ONNX Runtime.
When inference is executed with a tiny `float32` input of shape `[1, 1, 1, 1]`, the graph uses `Resize` with scales `[1.0, 1.0, 65536.0, 65536.0]` to produce output shape `[1, 1, 65536, 65536]`. This requires at least 17,179,869,184 bytes of output tensor memory. The local verification run times out during inference.
ModelScan does not scan ONNX files and reports `SCAN_NOT_SUPPORTED` with no issues.
##   ⟨39⟩ Files 
  * `onnx_resize_inference_dos.onnx`: PoC model file to upload to Hugging Face.
  * `build_and_verify.py`: Builds the model and verifies load, validation, shape inference, runtime behavior, and ModelScan result.
  * `verify_report.json`: Verification output from the local run.


##   ⟨40⟩ Reproduction

& C:\Users\mean\Desktop\bbg\.venv\Scripts\python.exe C:\Users\mean\Desktop\bbg\poc-onnx-resize-inference-dos\build_and_verify.py

Expected result:
  * model size is `189` bytes.
  * `onnx.load_model` succeeds.
  * `onnx.checker.check_model` succeeds.
  * `onnx.shape_inference.infer_shapes_path` succeeds.
  * `onnxruntime.InferenceSession` load succeeds.
  * inference times out because `Resize` attempts to materialize a huge output tensor.
  * ModelScan reports no issues and skips the ONNX file as `SCAN_NOT_SUPPORTED`.


##   ⟨41⟩ Impact 
An attacker can publish a tiny ONNX model that passes validation and loads normally, but causes resource exhaustion during inference from a very small input tensor. Automated systems that rely on ModelScan receive no warning because the ONNX file is not inspected. Downloads last month
