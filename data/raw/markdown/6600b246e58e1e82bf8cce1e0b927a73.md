#   ⟨56⟩ Ylemis India-PII Benchmark v1 
An open, reproducible benchmark for span-based PII detection in Indian and multilingual business text. The dataset is fully synthetic and is intended for evaluation, regression testing, and transparent comparison—not model training and not as a substitute for a customer-specific pilot.
##   ⟨46⟩ Release facts 
  * 10,000 cases, all synthetic; no intended real-person PII.
  * 16 entity types and 14 language/format slices.
  * 1,756 negative cases: 810 clean benign and 946 hard negatives.
  * Fixed seed: `20260630`.
  * Canonical `benchmark.jsonl` SHA-256: `7003719c62f451b68ec68280fbccaca12990718ad9ee7aacbcaba66c4c43f914`.
  * The file hash was verified against the Kaggle input used by the published Ylemis v5, GLiNER, and Presidio evaluation runs.


##   ⟨47⟩ Schema 
Each JSONL row contains:

```
{
  "id": "ylemis-india-pii-00000",
  "text": "...",
  "entities": [
    {"type": "pan", "start": 20, "end": 30}
  ],
  "language": "en-IN",
  "category": "kyc"
}

```

Offsets are zero-based character offsets with an exclusive `end`.
##   ⟨48⟩ Entity types 
`person`, `address`, `location`, `organization`, `account_id`, `medical_id`, `email`, `indian_phone`, `pan`, `aadhaar`, `gstin`, `ifsc`, `upi_id`, `voter_id`, `vehicle_registration`, and `indian_passport`.
##   ⟨49⟩ Language and format slices 
English (India), Hindi, Tamil, Bengali, Marathi, Gujarati, Telugu, Punjabi, Kannada, Hinglish/Latin Hindi, mixed-script text, code-mixed JSON, LLM/RAG text, and OCR-style synthetic text.

##   ⟨51⟩ Production artifact qualification 
The release-gated Ylemis artifact is FP32 ONNX. On the Kaggle CPU environment, using two threads, batch size one, and including tokenization, it measured:
  * p50: 22.74 ms
  * p95: 31.97 ms
  * p99: 36.91 ms
  * throughput: 41.57 texts/second


PyTorch-to-FP32 span-set and token-argmax agreement were both 100% on the parity set. INT8 was rejected: its span-set agreement against FP32 was 93.16%, below the 98% release gate. See `qualification/v5-fp32.json` for the raw report.
##   ⟨52⟩ Reproduce 
**Offline, no API calls (recommended)** — verify our exact score with zero load on the service and no quota used:

```
python run_benchmark.py --score-file ylemis_v5_live_outputs.jsonl --name ylemis-v5

```

`ylemis_v5_live_outputs.jsonl` holds our model's raw predictions on all 10,000 cases (one JSON array of `[type,start,end]` per line, aligned to `benchmark.jsonl`). To re-measure the live API yourself instead, call it **sequentially** (a single stream), not in large parallel bursts:

```
python run_benchmark.py --system api \
  --endpoint https://api.ylemis.com/pii-shield/v1/scan \
  --api-key "$YLEMIS_PII_SHIELD_KEY" \
  --name ylemis-v5

python run_benchmark.py --system gliner
python run_benchmark.py --system presidio

```

The API adapter sends `{"text":"..."}` and expects character spans under `entities`. Review `run_benchmark.py` before adapting it to another vendor.
##   ⟨53⟩ Files 
  * `benchmark.jsonl`: canonical evaluation data.
  * `manifest.json`: counts, seed, and canonical hash.
  * `build_benchmark.py`: deterministic generator.
  * `run_benchmark.py`: reference scoring and adapters.
  * `results/`: raw leaderboard outputs.
  * `qualification/`: raw deployment qualification report.
  * `leaderboard.json`: publication-ready result summary and provenance.


##   ⟨54⟩ Intended use and limitations 
  * Use this as a public, reproducible evaluation floor.
  * Keep a separate locked, audited benchmark for model selection so public test data does not become training data.
  * Synthetic data cannot prove performance on every real customer document.
  * OCR is not evaluated as an image-recognition pipeline. The OCR-style slice is text that simulates OCR noise.
  * Do not publish “best in the world” claims from this benchmark.
