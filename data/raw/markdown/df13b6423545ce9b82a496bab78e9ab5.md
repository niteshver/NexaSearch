#   ⟨51⟩ Music-CRS — RecSys 2026 Challenge (Team `volart`) 
A conversational music recommender for the RecSys Challenge 2026 — Music Conversational Recommendation System⟨52⟩. Given a conversation, it predicts an ordered list of **20 catalog tracks** and a **natural-language reply**.
This repository reproduces our **final Blind-B submission**. It is a clean, 3-stage **retrieve → rerank → respond** pipeline. The only trained component is a small LightGBM reranker, trained solely on the provided challenge train split. See COMPLIANCE.md⟨53⟩ for the full data/model disclosure.
* * *
##   ⟨36⟩ Quickstart (reproduce inference) 

```
# 0. Environment
uv venv && uv sync                 # or: python -m venv .venv && pip install -e .
cp .env.example .env               # then fill in OPENAI_API_KEY and GEMINI_API_KEY

# 1. Download precomputed artifacts (embeddings, indexes, trained reranker) from Hugging Face
python scripts/download_artifacts.py     # -> ./cache

# 2. Inference:  Blind-Dataset-B -> pipeline -> predictions.json
export MCRS_EVALUATOR_DIR=/path/to/music-crs-evaluator   # your evaluator checkout (Stage-3 lexdiv)
bash scripts/reproduce_inference.sh
# -> exp/runs/blind_b_final/prediction.json

# 3. (Optional) Retrain the reranker from scratch
bash scripts/train_reranker.sh     # -> cache/lambdamart/model_v9.txt

```

##   ⟨39⟩ Step 2 — Download artifacts 
The neural embeddings, sparse index, co-occurrence table, the trained reranker (`model_v9.txt`), its training feature matrix, and the deterministic API-response **replay caches** are hosted on Hugging Face. Fetch them into `./cache`:

```
python scripts/download_artifacts.py

```

The replay caches (`cache/openai_pipeline/`) reproduce the exact submitted **track lists** with **zero API spend** : the Stage-1/2 calls (query rewrite, entity extraction, embeddings) and the base reply are cached by `(session_id, turn)` and replayed. The Stage-3 quality passes (`refine`/`harden`/`lexdiv`) call the LLMs live — which is why the reply _text_ is not byte-reproducible (see "Reproducibility"). Delete a cache file to force live API calls for that stage.
##   ⟨40⟩ Step 3 — Inference (Blind-B → predictions.json) 

```
export PYTHONHASHSEED=0                                   # determinism (see below)
export MCRS_EVALUATOR_DIR=/path/to/music-crs-evaluator
bash scripts/reproduce_inference.sh

```

Output: `exp/runs/blind_b_final/prediction.json` — 80 sessions, each with 20 unique catalog-valid `predicted_track_ids` + a `predicted_response`. (Step 1 also writes a base `submission.zip`; the final deliverable is the post-chain `prediction.json`.)
`reproduce_inference.sh` runs four steps: (1) Stage 1+2 + base Stage-3 reply via `src.orchestration.run`, then the three reply-text-only Stage-3 passes (2) `refine`, (3) `harden`, (4) `lexdiv`. **To verify Stage-1/2 inference alone** (the deterministic track lists), step 1 is sufficient:

```
PYTHONHASHSEED=0 python -m src.orchestration.run --config config/blind_b_final.yaml --tid blind_b_final

```

```

`model_v9` is a LightGBM LambdaMART model (69 features, `seed=7`) trained on 5,000 provided-train sessions with a deterministic 1,500-session held-out subset excluded. The **fast path** trains on the provided feature matrix (`~1–2 min`, deterministic); the **full path** (commented in the script) rebuilds the feature matrix from raw via `build_dataset.py`. See COMPLIANCE.md⟨53⟩ for the training-data statement.

##   ⟨42⟩ Pipeline details 
###   ⟨43⟩ Stage 1 — Retrieval (top-500 candidate pool) 
Reciprocal-rank fusion (RRF) over five lanes:
  1. **Dense semantic** — OpenAI `text-embedding-3-large` over track metadata (track name, artist, album), cosine vs. the (rewritten) conversation query.
  2. **BM25 lexical** — `bm25s` over the same fields plus the catalog tag list.
  3. **Entity filter** — `gpt-4o-mini` extracts named artists / tracks / albums / era from the conversation; exact catalog matches are promoted.
  4. **LLM-description dense** — OpenAI embeddings over `gpt-4o-mini`-generated track descriptions (subgenre / era / mood).
  5. **Track co-occurrence** — computed over the **provided challenge-train dialogues only**.


A `gpt-4o-mini` **query rewriter** compresses the conversation into a one-line query.
###   ⟨44⟩ Stage 2 — Rerank (top-500 → top-20) 
LightGBM **LambdaMART** reranker (`model_v9`, 69 features). Deterministic given the candidate features. Defined in `src/reranker/lambdamart/features.py` (`FEATURE_NAMES`).
**Feature families (69 total) — all derived from provided data + retrieval signals; no external or leaked inputs:**  
| Family  | #  | What it captures  |  
| --- | --- | --- |  
| Retrieval  | 6  | dense (OpenAI) & BM25 scores + rank positions, entity-filter membership, fused `rrf_rank`  |  
| Candidate intrinsics  | 8  | popularity (+log), year/decade, tag count, in-history flag, listener-goal tag overlap  |  
| Conversation context  | 3  | turn number, has-history, number of played tracks  |  
| Cross-history "inertia"  | 6  | candidate artist/album matching recently/ever-played tracks, played-artist weighting, recent tag overlap  |  
| Category / specificity / profile one-hots  | ~22  | conversation category & specificity; plus `age_*`/`gender_*`/`culture_tag_overlap` from the **session's own`user_profile`** — null for the 40 cold-start Blind-B sessions, **not** an external demographic aggregate  |  
| Listener-goal × candidate + era stability  | 10  | text/era match between candidate and the listener's stated goal & played history  |  
| Mood-class overlap  | 4  | mood match between query and candidate  |  
| Train gold-frequency priors  | 3  | log frequency each track/artist/album was a correct answer in the provided train split  |  
| Track co-occurrence  | 3  | how strongly the candidate co-occurs with played tracks in the provided-train dialogues  |  
| MOVES-rate priors  | 3  | Bayesian-smoothed rate each track/artist/album moved listeners toward their goal in training  |  
Top drivers by gain: `rrf_rank` ≫ `coocc_sum_log`, `played_artists_weighted`, `last_played_artist_match`, `same_album_as_any_played`, `popularity`, `is_in_entity_filter`, `dense_cosine_openai`. The reverted exploit features (`track2vec_rrank`, `mpd_rrank`, `is_in_lastfm_lane`, aggregated demographic/temporal priors) are **not** in this set — see COMPLIANCE.md⟨53⟩.
###   ⟨45⟩ Stage 3 — Response (reply text only; tracks untouched) 
`gemini-3.1-flash-lite-preview` writes the reply from the top-3 tracks, then three reply-text-only quality passes — **refine → harden → lexdiv** — each gated on an **independent editorial critic** (`gpt-4o-mini`; a generic relevance + musical-specificity rubric). The competition LLM-as-judge model is never queried, sampled, or optimized against.

##   ⟨48⟩ Reproducibility notes 
  * **Determinism.** Run with `PYTHONHASHSEED=0` (the scripts export it). Without it, the RRF fusion / entity pre-pool resolve tie-breaks in Python hash-seed order, so a few sessions' rank-20 boundary can differ run to run. With it pinned, the **20-track lists are byte-identical across runs**.
  * **LLM non-determinism (Stage-3 text).** Reply text is generated by an LLM at temperature, so wording varies run to run — this is normal for any LLM pipeline. The **track lists** (which drive nDCG@20 and diversity) are fully deterministic; only the `predicted_response` prose differs. Our exact submitted `prediction.json` is included under `submission/` for reference.
  * **Exact model IDs** are pinned in code (`gpt-4o-mini-2024-07-18`, `text-embedding-3-large`, `gemini-3.1-flash-lite-preview`). If a provider deprecates one, the replay caches still reproduce our submitted output offline.
  * **Cost.** A full Blind-B run from warm caches is ~free (cached replay). A cold run (all APIs live) is a few US$ for the 80 sessions.

  retrieval/                  Stage 1 — dense/BM25/entity/description/cooccurrence lanes

cache/  (gitignored)          artifacts from Hugging Face — see Step 2

```

##   ⟨50⟩ Compliance 
This system was built under the challenge's Blind-B anti-manipulation policy. It uses no LFM-2B/listening-history data, no LLM-judge targeting, and no metric gaming (predictions are exactly 20 unique catalog tracks). Full disclosure: COMPLIANCE.md⟨53⟩.
