#   ⟨53⟩ D14 CodeGen Annotated — CAD code generation with chain-of-thought 
The **`code_gen`layer of D14 (BenchCAD)** with teacher-written reasoning: **17,900 records** , each `4-view orthographic render → reasoning → complete **CadQuery** program`. The `reasoning` ends with the complete program in a ```python block, and the program is **AST-equivalent to BenchCAD's execution-verified reference — asserted per record at assembly** (records whose regeneration drifted carry the reference spliced verbatim; correctness is never sampled).
Sibling releases: `AI4Manufacturing/D14-editbench-annotated`⟨54⟩ (the other trainable D14 layer) and `AI4Manufacturing/D14-vision-qa`⟨55⟩ (the Vision-QA layer — an evaluation probe, deliberately NOT training data).
##   ⟨49⟩ Pipeline (improve-never-drop) 
  1. **Generation** (Claude Sonnet 5, batched): gold-shown reasoning + code regeneration; hard no-leak prompt (the reasoning never references the provided program).
  2. **Deterministic checks** : AST code-equivalence, leakage regex, truncation.
  3. **Faithfulness screen** (Claude Sonnet 5 as grounded judge: sees the render + reference + reasoning): flags prose that misdescribes the part or narrates a construction different from the actual program.
  4. **Regeneration** of flagged records with the judge's critique; re-screened; kept only if clean. Stubborn records fall back to best-prose + pasted-gold code. **No record is dropped** ; every verdict is preserved in `metadata.cot`.


**Prose faithfulness: 86% of records score ≥3** (judge scale 1–5). The residual ~14% carry guaranteed-correct code with their (flagged) prose verdict documented in `metadata.cot` — filterable via `metadata.cot.screen.faithfulness` / `metadata.cot.method`.
##   ⟨50⟩ Schema 
Unchanged from the source (`query`, `image`, `annot`, `cate`, `task`, `other_files`) except: `reasoning` filled (prose + ```python program); `metadata` gains a `cot` provenance block (`annotator_model`, `method` = rationalized / rationalized_regenerated / rationalized_pasted / +code_pasted variants, `code_equivalent` (always true), screen + final judge verdicts). Reasoning prose may use light markdown structure (headers/bold), typical of code-reasoning corpora.
##   ⟨51⟩ Roles 
**Roles:** `reasoning` is the SFT imitation target — its terminal ````python` block is the model-facing deliverable; `annot` is the machine-parseable gold used for verification and reward parsing, **not** an output-format target.
##   ⟨52⟩ Provenance & caveats 
  * Derived from `AI4Manufacturing/benchcad_TB3E1_D14`⟨56⟩ (= **BenchCAD** , arXiv:2605.10865). Please cite BenchCAD.
  * `reasoning` is **teacher-generated and model-gated** , not human-verified; the reference programs are BenchCAD's execution-verified golds and are never altered.
  * BenchCAD is published as an evaluation benchmark; if you also evaluate on BenchCAD, note that training on this dataset contaminates that comparison.
