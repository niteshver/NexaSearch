#   ⟨67⟩ ARC-AGI Synthetic 
A dataset of **4,940** self-defining ARC-AGI-style reasoning tasks, authored as compressed Hy programs over a frozen DSL (`library.hy`) and materialized into raw input/output grids. Each task is a single transformation rule expressed as a constructive program for the inputs plus a structural `to-output` that derives every output from its input — so the rule is guaranteed self-consistent across all of the task's pairs.
This corpus was generated by an autonomous LLM agent (a `synth-task` worker spawned in parallel waves) that invents novel ARC-like rules, authors each task as a maximally-compressed Hy program, and self-validates it. The tasks span a broad set of rule families — Voronoi partitions, nesting-depth recolour, billiard-laser tracing, connectivity-degree colouring, symmetry completion, gravity/roll, bar-chart/tally, and many more.

##   ⟨61⟩ Why this dataset 
  * **Both code and grids.** Every row carries the full Hy source _and_ the evaluated input/output grids (ARC palette 0–9, list-of-lists, arckit-style). You can train on the grids like any ARC dataset, or read/execute the Hy code to inspect the exact generative rule.
  * **Self-consistent by construction.** One `to-output` is applied to every pair, so the transformation rule can't contradict itself across pairs.
  * **Executable.** `library.hy` is included in this repo, so every task's `.hy` code can be re-run end-to-end (see _How to run a task_ below).


##   ⟨62⟩ Schema   
| field  | type  | description  |  
| --- | --- | --- |  
| `id`  | string  | task id (e.g. `c01-w01-00`); encodes the authoring chunk/wave/instance  |  
| `hy_code`  | string  | full source of the task's `.hy` file  |  
| `rule`  | string  | short rule phrase extracted from the file's `;; RULE` header (best-effort)  |  
| `family`  | string  | heuristic rule-family bucket (see _Quality metrics_)  |  
| `train`  | list of `{input, output}`  | training pairs; each grid is a list-of-lists of int (0–9)  |  
| `test`  | list of `{input, output}`  | held-out test pair(s); last pair of the task  |  
| `objects`  | int  | object-count metric from the DSL (a compactness measure of the Hy program)  |  
| `n_pairs`  | int  | total input/output pairs (train + test)  |  
Grids are stored as nested Python lists (`[[int, ...], ...]`) using the ARC 0–9 palette. Train/test split per task: the last pair is held out as `test`, the rest are `train` (ARC convention).
##   ⟨63⟩ How to run a task's `.hy` code 
`library.hy` (included at the root of this dataset repo) is the frozen DSL every task is written against. With Hy⟨79⟩ and NumPy/SciPy installed, you can reconstruct every grid from a task's `hy_code`. Drop `library.hy` next to this script and run:

```
pip install hy numpy scipy

```


```
# run_task.py — reconstruct a task's grids from its hy_code
import sys, importlib.util
import hy, numpy as np
import library                       # the DSL shipped with this dataset

def load_task(hy_code, name="task"):
    spec = importlib.util.spec_from_loader(name, loader=None)
    mod = importlib.util.module_from_spec(spec)
    sys.modules[name] = mod
    hy.eval(hy.read("(require hyrule *)"), module=mod)   # threading macros
    for form in hy.read_many(hy_code):
        hy.eval(form, module=mod)                         # defines inputs / to-output
    return mod

mod = load_task(open("c01-w01-00.hy").read())
for i, expr in enumerate(mod.inputs()):
    inp = np.asarray(hy.eval(expr,            module=mod))   # 1..10 palette
    out = np.asarray(hy.eval(mod.to_output(expr), module=mod))  # 1..10 palette
    inp, out = inp - 1, out - 1                             # -> ARC 0..9 palette
    print(f"pair {i}: input {inp.shape}, output {out.shape}")

```

The internal palette is 1–10 (0 = UNSET/transparent); subtract 1 to recover the ARC 0–9 palette stored in this dataset's `train`/`test` fields.
##   ⟨64⟩ How it was generated 
An orchestrator agent fans out `synth-task` worker agents (Opus 4.8, max effort) that each invent one novel ARC-like rule, author it as a compressed Hy program with ≥4 distinct pairs (≥3 train + ≥1 test), and self-validate with `synthetic/validate.py`. Cross-chunk diversity steering nudges authors away from already-over-represented rule families. This build evaluates every authored `.hy` file against the frozen `library.hy`, keeps only the tasks that pass all quality gates, and materializes their grids.

##   ⟨66⟩ Notes & limitations 
  * The `rule` and `family` fields are best-effort, extracted from the author's free-form header comment — they're a search aid, not a clean label.
  * Tasks were authored across 16 chunks; some near-duplicate rules may exist across chunks despite diversity steering. The within-task uniqueness gate guarantees no _pair_ repeats inside a task, but not cross-task novelty.
  * `objects` is the DSL's object-count metric (count of "things placed"), not a token or character count — it measures how compactly the rule was expressed.
  * All grids use the ARC 0–9 palette. Internal Hy evaluation uses 1–10 (with 0 = UNSET/transparent); subtract 1 to recover the palette stored here.
