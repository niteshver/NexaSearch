#   ⟨53⟩ CALIBER — Calibrated Adaptive-effort Live-tool Instruction corpus for Benchmarked, Execution-verified Reasoning 
> **A tool-caller is best not when it thinks the most or holds the most instruments, but when it spends deliberation only where deliberation pays** — think hard on ambiguous / multi-step turns, act directly on unambiguous single-tool turns, and **abstain / ask / refuse** correctly — and every one of those decisions is execution/rubric-verified, decontaminated, and grounded in the real tools it will actually be handed.
CALIBER trains a **System-2 escalation tool-caller** (the _Helmsman_ model, `Jables/helmsman-qwen3-1.7b-v1`, a Qwen3-1.7B LoRA fine-tune) in the deployed **Hermes-XML** representation, so there is zero train/serve skew with the runtime that consumes it.
##   ⟨44⟩ 1. Motivation 
Two 2026 results frame the corpus:
  * **Ming (arXiv:2607.02467)** — on a Polymarket real-money forecasting benchmark, hybrid human-AI edge came from **complementary reasoning** , not raw model scale; blind deference to the biggest model _underperformed_.
  * **Mehta (arXiv:2607.02436)** — raising _reasoning effort_ lifted first-try-perfect agentic runs **28% → 89%** , while adding a _testing tool_ raised cost 42–68% with **zero** functional gain. Depth, not instrument count.


And the counter-weight, which we build _around_ rather than against:
  * **WHEN2TOOL (arXiv:2605.09252)** — whether a tool is _necessary_ is linearly decodable from a model's hidden state (AUROC 0.89–0.96), _beating_ verbalized CoT. So CALIBER does **not** claim "reasoning decides whether to call." It sells the parts a probe can't supply — **effort _suppression_** (don't emit System-2 theater on System-1 turns), multi-step plan synthesis, argument grounding, and first-class **abstain / clarify / refuse-destructive**.


The public tool-calling corpora that exist (ToolMind 360k, ToolACE, xLAM/APIGen, Hermes-FC, Nemotron-Agentic, When2Call) each own _some_ of this. **None owns the combination** that CALIBER targets:  
| Axis  | ToolMind  | xLAM/APIGen  | When2Call  | Hermes-FC  | **CALIBER**  |  
| --- | --- | --- | --- | --- | --- |  
| Multi-turn + reasoning traces  | ✅  | –  | –  | partial  | ✅  |  
|  **Adaptive effort labels** (System-1/2 + per-turn transitions)  | –  | –  | –  | –  | **✅**  |  
| First-class verified **abstain / clarify / refuse-destructive**  | –  | –  | ✅ (labels)  | –  | **✅**  |  
|  **Execution/rubric verification** (fail-closed, evidence certificates)  | –  | partial  | –  | –  | **✅**  |  
| Real **deployment-tool** grounding  | –  | –  | –  | –  | **✅**  |  
| Published multi-layer **decontamination** report  | –  | –  | –  | –  | **✅**  |  
The **per-turn, tool-result-conditioned effort transition** (think once early, then act directly on the unambiguous follow-ups in the same session) is the specific unit CALIBER introduces.
##   ⟨45⟩ 2. Construction 
Four-part playbook (auto-constructed verifiable environments → planner-coder rubric synthesis → three-tier reward pyramid → reject-sampling / RFT-Self):
  1. **Environment synthesis.** Each scenario is a deterministic tool-stub **state machine** over the real ZeroClaw tool schemas; the terminal state is exact-checkable (tau2-style state-delta, not string match). Faults (timeout/404/malformed) are injected by `(tool, nth-call)` for error-recovery scenarios.
  2. **Planner-coder rubric.** A planner drafts the scenario + acceptance rubric; a coder emits the executable stubs + per-instruction validator.
  3. **Teacher rollouts + reject-sample.** A per-difficulty teacher produces N candidate Hermes-XML trajectories with **adaptive** `<think>`; only rollouts that reach the expected terminal state **and** satisfy the rubric survive.
  4. **Causal-thinking filter.** For every System-2 row, the `<think>` is masked and the action re-derived; only rows whose action _materially changes_ are kept — decorative "thinking theater" is dropped.


The build pipeline is open in `scripts/finetune/adaptive-toolcall/`⟨54⟩.
##   ⟨46⟩ 3. Schema 
One JSON line per trajectory, `{messages, meta}`, ChatML + Hermes-XML:

```
{
  "messages": [
    {"role": "system", "content": "You are a tool-using assistant. Available tools:\n<tools>[...]</tools> ..."},
    {"role": "user", "content": "Sign me up for the newsletter using my usual email."},
    {"role": "assistant", "content": "<think>I must not guess an address — resolve it from memory first.</think>\n<tool_call>{\"name\":\"memory_recall\",\"arguments\":{\"query\":\"usual email\"}}</tool_call>"},
    {"role": "tool", "content": "{\"results\":[{\"content\":\"jane@dsynth.io\",\"type\":\"email\"}]}"},
    {"role": "assistant", "content": "..."}
  ],
  "meta": {
    "source": "toolcall_multiturn",
    "category": "multi_step",
    "reasoning_tier": "system2",
    "canary": "CALIBER-CANARY-...",
    "leak_hash": "sha256:...",
    "verification": {"method": "trajectory", "reward": 1.0, "checks": [...], "certificate": {...}}
  }
}

```

`category ∈ {simple_direct, multi_step, abstain_ask, abstain_refuse, parallel, wrong_premise, error_recovery, escalate}`; `reasoning_tier ∈ {system1, system2}`. System-1 turns carry **no** `<think>`. Matches `prepare-data.py` and the deployed `transformers-model.js` Hermes parser.
##   ⟨47⟩ 4. Splits 
**v1 (this release)** — a compact, fully-verified, decontaminated corpus. Depth over count (Mehta 2607.02436): every row is execution/rubric-verified, not scraped.  
| Split  | Rows  | Notes  |  
| --- | --- | --- |  
| `train`  | 383  | SFT source; per-split canary  |  
| `validation`  | 43  | auto-derived  |  
|  `test` (gated)  | 84  | held-out by FNV bucket (leak-disjoint from train), effort-stratified  |  
| `benchmark-multiturn.json`  | 155 cases  | turn-level decision gate  |  
_(v2: ~570 verified rows — v1's corpus**plus a contrastive arbitrary-tool family** (fit→call / no-fit→don't-call twins) added after external BFCL-v4 eval caught the v1 model over-calling on irrelevant tools. The v2.1 model trained on this corpus scores **BFCL simple 0.90 / irrelevance 0.77** (vs v1's 0.86 / 0.47) with its own official `ast_checker` — real, off-our-turf generalization. See the model card + `results-bfcl-v2.json`.)_
Sources: two frontier-teacher generation rounds (reject-sampled through the verifier) + an env-grounded parametric generator (deterministic, terminal-state-verified) + a hand-authored seed. **Roadmap:** v2 scales toward ~24k via more teacher rounds + RFT-Self curriculum (the pipeline is size-agnostic; `generate_adaptive.py --live` + `build_corpus.py` produce any N).
A matched **`benchmark-multiturn.json`**gates training and is scored per-tier (task accuracy,`abstentionAccuracy` , `overThinkRate`, `adaptiveEffortAccuracy`).
**Think-axis mix:** System-1 (no-think), System-2, and transition rows — deliberately inverting the public-data bias toward "call because a tool is present."
##   ⟨48⟩ 5. Decontamination statement 
> CALIBER was decontaminated in three layers — per-split GUID canary, n-gram verbatim overlap (13/8-gram + 50-char), and MiniLM cosine ≥ 0.85 — against BFCL-v4, tau2-bench, MCP-Bench, WHEN2TOOL, FC-RewardBench/TRBench, and our internal `benchmark-router.json` / `benchmark-multiturn.json` held-out keys. Removed rows are logged in `leak-report-*.json`. **Honest limitation:** n-gram catches only verbatim overlap and cosine catches paraphrase; neither catches reasoning-level or template-level leakage. **No dataset here is both training data and an evaluation gate.**

##   ⟨51⟩ 8. Limitations 
  * **WHEN2TOOL scope note:** a hidden-state probe out-predicts CoT on the bare call/no-call decision; CALIBER's value is effort suppression + plan/grounding/abstain, not "reasoning decides the call."
  * **Small-model reasoning capacity:** a 1.7B may under-reason on genuinely hard System-2 plans; the adaptive-effort reward is the guardrail, and this is the _escalation_ brain, not the <150 ms hot path.
  * **Synthetic-distribution caution:** synthetic scenarios can look strong in-domain and not move BFCL/tau2 — external benchmarks + an anti-collapse real-data floor are required, not optional.
  * **Judge/reward-hacking:** any rubric-labeled row is a drift/label-noise vector; the LLM-judge tier is BASE-gated, small-weight, different-family, and evidence-certificated — mitigated, not eliminated.
